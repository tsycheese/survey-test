OPERATIONS

本地生命周期

Soketi 容器无状态，业务数据与锁定信息仍由 PostgreSQL 保存。 

pnpm realtime:up
pnpm realtime:logs
pnpm realtime:down

为什么鉴权没变快？

约 55 ms 主要来自 NextAuth 会话与数据库权限查询；本地签名计算不足 1 ms。

广播失败怎么办？

记录 provider、operation、event 与 requestId；刷新或重连后从数据库恢复状态。

生产环境怎么选？

本阶段生产仍使用 Pusher Cloud。自托管需要额外评估高可用、监控与扩缩容。

结论

本地 Soketi 将开发环境暖广播从 220.6 ms 降至 6.4 ms，减少 97.1%，同时让连接和订阅反馈更稳定。更重要的是，实时服务已经退出业务响应关键路径：外部网络波动不再决定保存操作是否成功。

  • 开发：使用本地 Soketi，获得稳定、快速、可离线的实时调试。
  • 生产：继续使用 Pusher Cloud，保留托管服务的运维优势。
  • 一致性：以 PostgreSQL 为最终事实来源，实时层负责低延迟通知。
